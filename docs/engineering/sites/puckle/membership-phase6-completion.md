# Puckle membership — Phase 6 completion (isolated onboarding)

15 November 2026, branch `site/puckle`, on top of `61dc953`. Local only: disposable databases, simulated email; no push, merge, deploy, live data or provider configuration.

## Implemented
- **One isolated client host** (`src/components/onboarding/OnboardingHost.tsx`), mounted once as a sibling after `{children}` in `src/app/layout.tsx` (still a synchronous Server Component; no auth/site/database work in the root). It renders nothing on the server or during hydration (`useSyncExternalStore`), supplies no props/context/keys to the application, never calls `router.refresh`, and lazy-loads its view behind a local error boundary: any import, fetch or render failure just makes it disappear.
- **Eligible routes:** exactly `/decks` and `/library`. No request is made anywhere else (Creator, Progress, detail routes, public pages, Step Visuals, login).
- **First welcome** (Puckle students whose profile is `welcome.eligible` and not `seenAt`, owned by the server): "Request a free session" (leaves for the existing `/#early-access` tuition form; creates no enquiry or booking) and "Explore Puckle" (dismisses). Ages under 16 also get the optional guardian-email section (send now, or skip by exploring) using the real Phase 5 request endpoint; 16+ and teachers do not. Acknowledgement (`welcome.seenAt`) is sent only once the expanded welcome has actually been presented, is idempotent, and a failure only means it may show again. Welcome takes priority and dismissing it never triggers a replacement popup.
- **Later reminders** (small, bottom-left, dismissible, quiet): not-requested offers setup; pending shows truthful status and delivery with a resend; declined and withdrawn show truthful status with an explicit ask-again; approved shows nothing. Turning 16 ends the reminder; unknown DOB shows nothing (support link only inside the under-16 content). Dismissal changes no approval.
- **Never intrudes:** auto-expands whenever its content arrives if the visitor has not yet interacted outside onboarding (no 2-second deadline). After an early outside pointer/key/wheel interaction (passive, bubbling, non-cancelling listeners) it collapses to a quiet control that opens the welcome only on request, without acknowledging an unseen welcome. It hides itself while fullscreen media, a native or rendered modal dialog, or either expanded Deck introduction (`.deck-grid-intro-host--expanded`, `.deck-intro-viewer-host--expanded`) is present (predicate in `onboardingPresentation.ts`, class-attribute observers on the two intro hosts only, evaluated on entry, focus, pageshow, fullscreenchange and after outside interactions).
- **Lifecycle:** revalidation only on eligible entry, same-tab auth changes, focus and pageshow (coalesced 400 ms). No polling, timers, storage, BroadcastChannel or session-expiry timers. Late responses are discarded by a generation counter; leaving the route aborts. Sensitive content is concealed while identity is re-confirmed. A guardian-email draft survives ordinary blur/visibility changes for the same actor; a different actor, a 401 or sign-out clears it; an uncertain network failure hides everything. Every mutation carries `expectedUserId`, which the server checks.
- **Approved notifications:** `src/lib/authSessionEvents.ts` (non-throwing, data-free same-tab event) called from `AuthScreen.tsx` (after successful login, before the existing replace/refresh), `LogoutButton.tsx` and `OverviewMenu.tsx` (after success/cleanup, before refresh). An explicit sign-in/out counts as a new session, so a fresh welcome is not collapsed by the sign-in click itself.
- **Server:** `GET/POST /api/account/onboarding` (`src/lib/onboarding.ts`): own-account status (actor id, welcome pending, shared approval summary with masked guardian, no DOB) and an idempotent acknowledgement that never creates a profile. No-store, `Vary: Cookie`; other sites get `show: false`.
- **Phase 3 completion message is untouched** (no timing or text change). Phase 6 serves its own purpose after navigation to My Decks.
- **Approved Phase 5 decision applied:** the Puckle privacy page names Puckle, Switchplay and Strat17 for shared account data and parental approval; the site-independence naming rule has one exception, for that single file only.

## Practical limits (honest)
Session expiry or turning 16 while a tab sits idle is noticed on the next focus/pageshow/entry and on every server mutation, not at the moment it happens. Native `<dialog>` open/close does not generate events we listen for, so it is detected on the next interaction/focus evaluation. The blocking selectors couple to current application class names and are covered by browser tests. The 400 ms focus coalescing means two focus events inside it trigger one request. Real iOS keyboard/scroll behaviour, production caching of the root layout and timing measurements are Phase 8.
